# 字典正则使用说明

`normaldict.json` 的文件名数组里可以混用普通文件名和正则规则。

普通文件名：

```json
"ini": [
  "message.ini"
]
```

正则规则需要以 `regex:` 开头：

```json
"ini": [
  "regex:^option_(1sys|2mes|3snd|4dlg|5vo|6key)\\.ini$"
]
```

## 支持的正则子集

为了保证撞库时可以有限展开，目前只支持这些写法：

- 字面量字符，例如 `message`
- 分组：`(a|b|c)`
- 字符组和范围：`[abc]`、`[0-9]`
- 可选项：`?`
- 固定/范围重复：`{3}`、`{1,3}`
- 转义字符：`\\.`, `\\d`, `\\w`
- 行首/行尾锚点：`^`、`$`

不支持会导致无限或过大展开的写法：

- `.*`
- `.`
- `+`
- `(?:...)`
- `[^...]`

单条 `regex:` 展开数量上限是 `10000`。超过上限时，主控生成字典会停止并提示具体规则；DLL 撞库时也会跳过该规则。

## 推荐写法

尽量写成精确范围，不要写过宽。

推荐：

```json
"ogg": [
  "regex:^BGM(0[2-9]|1[0-8])(_LOOP)?\\.ogg(\\.sli)?$"
]
```

不推荐：

```json
"ogg": [
  "regex:^BGM\\d{2}.*\\.ogg$"
]
```

## 版本尾缀

主控生成 filedict 时，会给 `normaldict` 里的普通文件名自动补版本尾缀规则。

默认不开 Steam 时，会生成：

```text
_1 ~ _9
_a ~ _z
```

例如 `message.ini` 会额外覆盖：

```text
message_1.ini
message_2.ini
message_a.ini
...
```

开启 Steam 版本匹配时，会额外放宽到两位数字、两位字母、字母数字混合等后缀。这个模式会明显增加撞库数量。

## 当前读取规则

当前主控只读取：

```text
scr/dict/normaldict.json
```

不会自动读取 `scr/dict/` 下所有 JSON。`newdict.json` 是程序生成的输出文件，不会作为通用字典输入。
