# KaguyaMsgTool使用说明	——by ChihanaSonnetia

> 原作者：crskycode  
> 原项目地址：https://github.com/crskycode/Kaguya_Tool  
> 现项目地址：https://github.com/SummerAdrenk/ChihanaReloading/tree/main/Kaguya/KaguyaScriptEngine/MsgTool  
> 版本: 1.5.0  
> 功能: 导出/导入 KaguyaScriptEngine（アトリエかぐや BARE＆BUNNY&アトリエかぐや Honky-Tonk Pumpkin）的 message.dat 【[SCR-MESSAGE]ver4.0版本】脚本文件，用于机翻。
----------------------------------------------------------------------
## ■ 1、功能简介

> - [导出] 从 message.dat 文件中提取所有的对话、人名、选项文本，并生成一个UTF-8编码的 .txt 文件。
> - [导入] 读取翻译好的 .txt 文件，将其内容重新写入，并生成一个新的 .new.dat 脚本文件。
> - [加密处理] 能够自动检测并处理文件的XOR加密。
> - [config配置] 通过 config.ini 文件，支持自定义人名等占位符，并可在重新封装时强制指定加密选项。
> - [编码检测] 在使用 GBK 编码导入时，会自动检测并报告所有不兼容的字符，防止出现乱码。
> - [编码覆盖] 通过预留的读取写入编码设置，覆盖通过命令行输入的编码
----------------------------------------------------------------------

### 通过 cmd.exe 或 PowerShell 来运行并查看详细信息。

## ■ 3、文本说明

> - 程序会将剧本提取成三个模块【Names（人名）、Choices（选项）、Dialogue Flow（文本）】  
	人名区：◆A00000001◆  
	选项区：◆B00000001◆  
	对话区：◆C00000001◆  
   #仅对话区会区分name与msg，其中name是用于辅助的参考信息，不会被注回。  

> - 格式内容如下：  
>  ◇A00000000◇【主人公】  
>  ◆A00000000◆【主人公】  
>
>   ◇C00000001◇msg◇今天天气真好啊。  
>   ◆C00000001◆msg◆今天天气真好啊。  

> ## 翻译规则:
>- `◇`开头的行是【原文】，仅供参考，程序在导入时会【忽略】此行内容。  
>- `◆`开头的行是【译文】，程序在导入时会【读取】此行的内容。  
翻译规则:  
> - 修改 `◆` 符号后面的文本即可！  
   请不要删除或修改 `◇...◇` 和 `◆...◆` 这些标记，只修改标记后面的译文。  
>  
>- 值得一提的是，msg后标记为branch的为自定义人名与默认人名分支处理：  
  ◇C00000006◇name◇碧桜  
  ◆C00000006◆name◆碧桜  
>
>   ◇C00000006◇msg◇branch01◇「ただ、[FirstName]がどんな想像してるか解らないけど、\n多分その何十、いや何千倍も凄い屋敷だよ」\n  
   ◆C00000006◆msg◆branch01◆「ただ、[FirstName]がどんな想像してるか解らないけど、\n多分その何十、いや何千倍も凄い屋敷だよ」\n  
>  
>   ◇C00000007◇name◇碧桜  
>  ◆C00000007◆name◆碧桜  
>
>   ◇C00000007◇msg◇branch02◇「ただ、キミはどんな想像してるか解らないけど、\n多分その何十、いや何千倍も凄い屋敷だよ」\n  
>  ◆C00000007◆msg◆branch02◆「ただ、キミはどんな想像してるか解らないけど、\n多分その何十、いや何千倍も凄い屋敷だよ」\n

## ■ 4. config配置 (config.ini)

### config.ini文件允许进行整花活，通常不需要修改。

> - 【ConfigurationID】:  
  用于选择要加载的配置方案。  
  例如: "ConfigurationID= 1" 会加载 "■[1][イチャ姉！]`" 下的配置。  
  通常使用ID为0的默认配置。
>
> - 【占位符 (Placeholder)】:  
  形如 "[FirstName] = F040" 的设置。  
  这用于处理游戏中的自定义人名等，导出的文本中会显示为 "[FirstName]"，  
  注回时程序会自动将其转换回游戏能识别的十六进制码 "F040"。
>
> - 【占位符显示长度】:  
  形如 "[FirstName]_Len = 2" 的设置。  
  这用于处理游戏中的自定义人名等的显示长度，用于后续的长度检测与修正  
  例如自定义名为李明，则长度为2字符，设置里就填写2。  
  如果没有设置对应的长度，程序则会默认设置为3字符。  
>
> - 【加密配置[XOR]】: 简单的XOR加密  
> "EncryptEnabled= True":   
  设为 "True" 时，注回时会使用下面指定的密钥进行加密。  
  设为 "False" 则不加密。  
> "EncryptKey= FF": 指定封装时使用的加密密钥（十六进制）。
>
> - 【自定义人名特殊处理[AdjustBranchMessages&AdjustMsgID&AdjustMsgDetails]】:  
  注意msg组后标记branch的内容，有的时候引擎并不会去管哪个是自定义人名，  
  而是直接去读第一个branch，这时就需要启用该功能，  
  不过需要你逐一确认是否修改正确。  
> - 【交换自定义人名行】"AdjustBranchMessages= True":   
	设为 "True" 时，  
  若仅有两个branch: 会将msg组后标记branch的branch01与branch02内容互换；  
	若有多个branch: 则根据AdjustMsgID的内容，将branch01与branch{AdjustMsgID+1}内容互换。  
>
>   "AdjustMsgID= 1": 设置多个branch要交换的branch对象ID。  
> "AdjustMsgDetails= True": 设为 "True" 时，会显示AdjustBranchMessages进行的修改操作信息。
> 
> - 【GBK编码校验】"GBKCheck":  
  顾名思义，在回注时检测文本内是否有非GBK的违法字符。
>
>   【编码覆盖】"ReadingEncoding/WritingEncoding":  
  通过预留的读取写入编码设置，覆盖通过命令行输入的编码
>
> - 【长度校验与长度修正】[MsgLengthCheck&MsgLengthFix]:  
  kaguya引擎有一行最大显示数的限制，超字数会超框，因此有以下处理。  
  值得注意的是，文本框的最大显示数与BACKLOG的最大显示数并不相同，因此我们取其中的最小值。  
  以下模式同时会检查文本是否以\n结尾、是否≤3行[最大显示行]等。  
  其中我们规定占位符全部为3字符。 
>   
>   "MsgLengthCheck= True":   
  检测一行的字符数是否符合MsgLengthSet设定的一行最大显示数  
  [25为Simhei的最舒适的显示数]  
>
>   "MsgLengthFix= False":   
  去除所有换行符后根据MsgLengthSet设定的一行最大显示数重新划分换行符  
>
>   "MsgLengthSet:  
  设置一行显示数，用于检测

## ■ 5. message.dat 文件结构  

> 整个文件可以看作是由一个固定的文件头和四个连续的数据区块组成的。  
> 其中，前三个数据区块的内容是加密的，最后一个区块是明文的。  
<br>
### a. 文件头 (Header) - [共 21 字节]
 这是文件的身份标识，固定大小。

| 偏移量 (字节) | 大小 (字节) | 注释 |
| :--- | :--- | :--- |
| `0x00` | 19 | 固定的版本标识: `[SCR-MESSAGE]ver4.0` (ASCII 编码) |
| `0x13` | 1 | 加密标志: `0x01` 代表加密, `0x00` 代表不加密。 |
| `0x14` | 1 | XOR加密密钥: 0-255 的一个字节值，例如 `0xFF`。 |

<br>

### b. 数据区块

#### 1): 人名列表 (Name List) - [大小可变, XOR加密]
> *#紧跟在文件头后面，存储了所有人名。*

| 大小 (字节) | 注释 |
| :--- | :--- |
| 4 | **人名总数**: 一个32位整数，表示后面有多少条人名数据。 |
| *循环开始* | *对列表中的每一个人名，重复以下结构* |
| 2 | **人名长度**: 一个16位整数，表示后面名字数据的字节长度。 |
| 可变 | **人名数据**: 人名经过目标编码后的字节数组。 |
| *循环结束* | |

> **加密说明**: 在写入文件时，每一条 **【名字数据】** 的字节数组都会被文件头中指定的 **【加密密钥】** 进行逐字节异或(XOR)加密。

<br>

#### 2): 选项列表 (Choice List) - [大小可变, 加密]
> *#结构与人名列表完全相同，存储了所有的选项文本。*

| 大小 (字节) | 注释 |
| :--- | :--- |
| 4 | **选项总数**: 一个32位整数。 |
| *循环开始* | *对列表中的每一个选项，重复以下结构* |
| 2 | **选项长度**: 一个16位整数。 |
| 可变 | **选项数据**: 选项文本经过目标编码后的字节数组。 |
| *循环结束* | |

> **加密说明**: 与人名列表一样，每一条 **【选项数据】** 都会被加密。

<br>

#### 3): 文本列表 (Message List) - [大小可变, 加密]
> *#它由一个个“文本块”组成。*

| 大小 (字节) | 注释 |
| :--- | :--- |
| 4 | **文本总数**: 一个32位整数，表示后面有多少个文本块。 |
| *循环开始* | *对列表中的每一段文本，重复以下结构* |
| 4 | **文本总长度**: 一个32位整数，表示后面 **【整个文本块】** 的长度。 |
| 可变 | **文本块数据**: 见下方的“文本块内部结构”说明。 |
| *循环结束* | |

> **加密说明**: 这里的加密是针对整个 **【文本块数据】** 进行的。程序会先在内存中构建出完整的明文文本块，然后对这个块整体进行XOR加密，最后再写入文件。

<br>

#### 3.1): 文本块内部结构

| 大小 (字节) | 注释 |
| :--- | :--- |
| 4 | **对话文本长度**: 32位整数，表示后面对话文本的字节长度。 |
| 可变 | **对话文本数据**: 对话经过目标编码后的字节数组。 |
| 1 | **语音文件数量**: 8位整数，表示这个对话关联了多少个语音文件名。 |
| *循环开始* | *对每一个关联的语音文件名，重复以下结构* |
| 可变 | **语音文件名**: 语音文件名字符串 (例如 `"voice001.wav"`) 的 Unicode 字节。 |
| 2 | **语音名结束符**: 固定的 `0x0000`。 |
| *循环结束* | |

<br>

#### 4): 命令列表 (Command List) - [大小可变, 不加密]
> *#文件的最后一部分，用于控制游戏逻辑，例如哪个角色说话、显示哪个背景等。这个区块的数据是明文的，不会被加密。*

| 大小 (字节) | 注释 |
| :--- | :--- |
| 4 | **命令总数**: 一个32位整数。 |
| *循环开始* | *对列表中的每一个命令，重复以下结构* |
| 4 | **命令ID**: 32位整数，通常关联到人名ID或其他功能。 |
| 1 | **参数数量**: 8位整数，表示该命令有多少个参数。 |
| 参数数量*4 | **参数数据**: 连续的32位整数参数列表。这些参数通常是消息ID，用于关联对话。 |
| *循环结束* | |
